## 1. 数据金字塔：分层数据策略

### (a) 核心困境

VLA 模型面临的最根本挑战是：**高质量机器人动作数据极度稀缺**。

```
数据量对比 (数量级差距):
═══════════════════════════════════════════════════

互联网文本:   ████████████████████████████████  ~10¹³ Token
互联网图文对: ██████████████████████████        ~10¹⁰ 对
互联网视频:   ████████████████████              ~10⁸ 小时
人类活动视频: ██████████████                    ~10⁶ 小时
机器人遥操作: ████                              ~10³ 小时 ← 差了 10 个数量级！
```

**根本原因**：机器人遥操作数据采集极其昂贵——每小时数据需要一个人类操作员实时控制一台真实机器人，成本高、速度慢、安全风险大。

### (b) GR00T N1 数据金字塔 (NVIDIA, 2025)

NVIDIA GR00T N1 提出了**数据金字塔 (Data Pyramid)** 的分层策略，将不同来源的数据按规模和质量分层使用：

```
                    数据金字塔
                    ──────────

                        ╱╲
                       ╱  ╲         第 3 层: 真实机器人遥操作
                      ╱ 88h ╲       ─────────────────────────
                     ╱  真实  ╲     • 人类操作员遥操作真实机器人
                    ╱  机器人  ╲    • 动作精确、物理真实
                   ╱───────────╲   • 极其昂贵，88 小时
                  ╱             ╲
                 ╱   827h 仿真   ╲   第 2 层: 合成数据 (Synthetic)
                ╱   + 神经轨迹    ╲  ─────────────────────────
               ╱                  ╲  • 神经轨迹: 视频生成模型 (10×)
              ╱    6500h 仿真轨迹   ╲ • 仿真轨迹: DexMimicGen 
             ╱──────────────────────╲  (780K 条, 6500 小时)
            ╱                        ╲
           ╱      互联网/人类视频       ╲ 第 1 层: 大规模无标注视频
          ╱       (Ego4D, Epic-K)      ╲ ─────────────────────────
         ╱          ~10⁶ 小时           ╲ • 海量人类活动视频
        ╱────────────────────────────────╲ • 无动作标注
       ╱          Web 数据 (文本/图文)      ╲ • 用于学习视觉语义 + 提取潜在动作
      ╱──────────────────────────────────────╲
```

### (c) 每层数据的角色

| 层级 | 数据来源 | 规模 | 动作标注 | 主要贡献 |
|:----:|:------:|:----:|:------:|:------:|
| **第 1 层 (底层)** | 互联网视频 + Web 数据 | ~10⁶ 小时 | ❌ 无 → **LAPA 提取潜在动作** | 视觉语义理解 + 通用操作知识 |
| **第 2 层 (中层)** | 神经轨迹 + 仿真数据 | ~7000 小时 | ⚠️ 伪动作 (IDM / 仿真导出) | 反事实场景 + 大规模多样化 |
| **第 3 层 (顶层)** | 真实机器人遥操作 | ~88 小时 | ✅ 精确真实动作 | 物理精确性 + 领域适应 |

### (d) 金字塔的训练策略

```
训练阶段映射:
═══════════════════════════════════════

阶段 1: 预训练 (Pre-Training)
─────────────────────────
  使用: 全部三层数据 (混合训练)
  目标: 学习通用的视觉-语言-动作关联
  数据量: 数千小时
  关键: 不同层的数据用不同的 loss 权重
       真实数据权重 > 合成数据 > 视频数据

阶段 2: 后训练 (Post-Training)
─────────────────────────
  使用: 仅第 3 层 (目标具身的真实数据)
  目标: 适配特定机器人的物理特性
  数据量: ~88 小时 (单一具身)
  关键: 小数据量但高质量
       微调而非从头训练
```

> **核心洞察**：金字塔每上升一层，数据量减少但质量（对VLA的直接有用性）和精确度提升。最终模型的性能由**所有层的共同贡献**决定——去掉任何一层都会导致性能下降。

## 2. 潜在动作提取：从人类视频中学习

### (a) 问题定义

互联网上有海量的人类活动视频（做饭、组装、清洁等），这些视频包含丰富的操作知识，但**没有机器人动作标注**。

```
问题:
═══════════════════════════════════════

  人类做饭视频 (YouTube):
  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐
  │帧 t │→│帧t+1│→│帧t+2│→│帧t+3│
  │ 🥕  │ │ 🔪🥕│ │ 🔪  │ │ 🥗  │
  └─────┘ └─────┘ └─────┘ └─────┘
    ↓        ↓        ↓        ↓
  观测 ✅   观测 ✅   观测 ✅   观测 ✅
  动作 ❌   动作 ❌   动作 ❌   动作 ❌  ← 没有机器人关节角度！

  如何利用这些视频训练 VLA？
```

### (b) LAPA: 潜在动作预训练 (Latent Action Pre-training)

**LAPA (Latent Action Pre-training for general Action models)** 是 GR00T N1 使用的核心数据提取方法，通过 **VQ-VAE** 从连续视频帧中提取**潜在动作 (Latent Actions)**：

```
LAPA 两阶段流程:
═══════════════════════════════════════

阶段 1: 训练 Latent Action VQ-VAE
──────────────────────────────────

  输入: 连续两帧图像 (oₜ, oₜ₊₁)

  ┌──────┐  ┌──────┐
  │ 帧 oₜ│  │帧oₜ₊₁│
  └──┬───┘  └──┬───┘
     │          │
     └────┬─────┘
          ↓
  ┌──────────────┐
  │  编码器 E(·)  │  ← 接收两帧的差异信息
  └──────┬───────┘
         ↓
  ┌──────────────┐
  │  VQ 量化层    │  ← 将连续潜在向量量化为离散码本
  │  (Codebook)  │     z = Quantize(E(oₜ, oₜ₊₁))
  └──────┬───────┘
         ↓
     潜在动作 z ∈ {1, 2, ..., K}    K = 码本大小
         ↓
  ┌──────────────┐
  │  解码器 D(·)  │  ← 从 oₜ 和 z 重建 oₜ₊₁
  └──────┬───────┘
         ↓
     重建帧 ô_{t+1}

  训练 Loss:
  L = ||ô_{t+1} - o_{t+1}||² + β · L_commitment
```

$$\mathcal{L}_{\text{LAPA}} = \| D(o_t, z) - o_{t+1} \|^2 + \beta \cdot \| \text{sg}[E(o_t, o_{t+1})] - e \|^2$$

其中 $z = \text{Quantize}(E(o_t, o_{t+1}))$，$e$ 是码本嵌入，$\text{sg}[\cdot]$ 是梯度停止操作。

```
阶段 2: 用潜在动作预训练 VLA
──────────────────────────────────

  对每段人类视频:
  ┌──────┐  ┌──────┐
  │ 帧 oₜ│  │帧oₜ₊₁│
  └──┬───┘  └──┬───┘
     │          │
     └────┬─────┘
          ↓
  ┌──────────────┐
  │ 冻结的 VQ-VAE │  ← 用阶段 1 训练好的模型
  └──────┬───────┘
         ↓
     潜在动作 z (离散 token)

  然后将 VLA 训练为:
     输入: 观测 oₜ + 语言指令
     输出: 预测潜在动作 z

  → VLA 学会了 "看到这个场景 + 这个指令 → 应该做什么动作"
  → 即使没有真实机器人动作标注！
```

### (c) 为什么 LAPA 有效？

| 能力 | 解释 |
|:----:|:----:|
| **捕捉帧间变化** | 潜在动作 z 编码了两帧之间"发生了什么"，这本质上就是"动作"的视觉效果 |
| **动作不可知** | z 不绑定任何特定机器人的关节空间，是具身无关的 |
| **可迁移** | 人类"抓取杯子"和机器人"抓取杯子"的视觉效果相似 → z 可迁移 |
| **大规模** | 可在数百万段互联网视频上训练 → 学到极其丰富的操作知识 |

### (d) LAPA 的数学本质

LAPA 学到的潜在动作空间可以看作是一个**视觉效果空间 (Visual Effect Space)**：

$$z = f_{\text{visual\_effect}}(o_t, o_{t+1}) \approx g_{\text{action}}(a_t)$$

即：两帧之间的视觉变化 $\approx$ 某个动作的效果。这构建了一个桥梁：

```
  人类视频中的帧间变化
         ↓ (LAPA 编码)
  潜在动作 z
         ↓ (后训练对齐)
  真实机器人动作 a = [Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]
```

> **GR00T N1 实验结果**：使用 LAPA 预训练 + 真实机器人数据后训练，相比只用真实数据训练，任务成功率提升 **15-25%**。

## 3. 神经轨迹生成：视频生成模型的反事实数据

### (a) 动机

即使有了 LAPA 可以利用人类视频，真实机器人数据的**多样性**仍然不足——同一任务的不同变体（不同物品位置、不同光照条件、不同背景等）覆盖有限。

### (b) 核心思想

**神经轨迹 (Neural Trajectories)** 利用**视频生成模型**（如 WAN2.1-I2V-14B）来合成大量**反事实 (counterfactual)** 的机器人操作视频：

```
神经轨迹生成流程:
═══════════════════════════════════════════════════

Step 1: 微调视频生成模型
────────────────────────────
  基础模型: WAN2.1-I2V-14B (大型图生视频模型)
  微调数据: 88 小时真实遥操作视频
  目的: 让视频模型学会生成"看起来像真实机器人操作"的视频

  ┌──────────────────┐      ┌──────────────────┐
  │ 通用视频生成模型  │  →   │ 机器人操作视频   │
  │ (WAN2.1-I2V)     │ 微调  │    生成模型      │
  └──────────────────┘      └──────────────────┘

Step 2: 从真实数据的首帧生成反事实视频
────────────────────────────
  输入: 一张真实场景的首帧图片 + 文本指令
  输出: 多个不同的操作视频 (同一起始状态，不同执行方式)

  真实首帧 ──→ 生成 10 个不同的操作视频
               │
               ├→ 视频 1: 从左侧抓取 (原始)
               ├→ 视频 2: 从右侧抓取 (反事实)
               ├→ 视频 3: 更慢的速度     (反事实)
               ├→ 视频 4: 稍微不同的角度  (反事实)
               ├→ ...
               └→ 视频 10: 另一种抓取策略 (反事实)

Step 3: VLM 质量过滤
────────────────────────────
  用 VLM (如 GPT-4V) 作为裁判:
  "这个视频展示了一个机器人成功完成任务吗？"
  
  ┌────────┐   VLM 评分   ┌────────────────┐
  │生成视频 │ ──────────→  │ 是否物理合理?  │
  └────────┘              │ 是否完成任务?  │
                          │ 动作是否流畅?  │
                          └───────┬────────┘
                                  ↓
                          保留高分视频 (约 60-70%)

Step 4: 为合格视频添加动作标注
────────────────────────────
  方法 A: IDM (逆动力学模型) 预测伪动作
  方法 B: LAPA 提取潜在动作
  → 合成视频 + 动作标注 = 可用训练数据
```

### (c) 数据扩增效果

| 数据类型 | 原始 (真实) | 神经轨迹 (合成) | 扩增倍数 |
|:--------:|:----------:|:--------------:|:-------:|
| 遥操作视频 | 88 小时 | 827 小时 | **~10×** |
| 轨迹数量 | ~30K | ~300K | **~10×** |
| 场景多样性 | 实验室环境 | 反事实变体 | **显著提升** |

### (d) 为什么视频生成模型适合做这件事？

```
关键洞察:
═══════════════════════════════════════

  大型视频生成模型 (如 WAN2.1, Sora) 已经从互联网视频中学到了:
  
  1. 物理常识 → 物体不会凭空消失，会受重力影响

  微调后:
  ┌──────────────────────────────────────────────┐
  │  视频生成模型 ≈ 一个"隐式物理模拟器"            │
  │                                              │
  │  输入: 初始场景 + 指令                         │
  │  输出: 物理合理的机器人操作视频                  │
  │                                              │
  │  优势: 比传统仿真器更逼真 (视觉真实感)           │
```

## 4. 仿真轨迹生成：DexMimicGen

### (a) 问题

传统仿真器可以无限生成数据，但需要人工编写任务脚本或提供大量演示。**如何自动化地从少量演示中生成海量仿真数据？**

### (b) DexMimicGen 原理

DexMimicGen (MimicGen 的灵巧操作扩展) 通过**分解-变换-重组**策略，从少量人类演示中自动生成大量新的仿真轨迹：

```
DexMimicGen 流程:
═══════════════════════════════════════════════════

Step 1: 任务分解 (Decomposition)
────────────────────────────
  将一个演示分解为与物体交互的子任务:

  演示: "抓取杯子放到盘子上"
    ↓
  子任务 1: 接近杯子 (approach cup)
  子任务 2: 抓取杯子 (grasp cup)
  子任务 3: 移动到盘子上方 (move to plate)
  子任务 4: 放下杯子 (place cup)

  每个子任务以"物体中心坐标系"表示:
    T_subtask = T_object_to_ee  (物体到末端执行器的相对变换)

Step 2: 场景变换 (Transformation)
────────────────────────────
  将物体放到新位置 → 子任务自动适配:

  原始:  杯子在 (0.3, 0.1, 0.8)
  新场景: 杯子在 (0.5, -0.2, 0.8)

  T_new_subtask = T_new_object · T_object_to_ee
  → 自动计算新位置下的动作序列

Step 3: 轨迹回放与验证 (Replay & Verify)
────────────────────────────
  在仿真器中执行变换后的轨迹:
  ┌──────────────────────────────┐
  │  物理仿真器 (Isaac Sim)       │
  │  执行变换后的动作序列          │
  │  检查: 是否成功完成任务?       │
  │  保留: 成功的轨迹              │
  │  丢弃: 失败的轨迹 (物理碰撞等) │
  └──────────────────────────────┘
```

### (c) DexMimicGen 的数据规模

| 指标 | 数值 |
|:----:|:----:|
| 源演示数量 | ~100 条高质量演示 |
| 生成轨迹数量 | **780,000** 条 |
| 等效操作时长 | **6,500 小时** |
| 生成耗时 | **仅 11 小时** (GPU 集群) |
| 扩增倍数 | **~7,800×** |

### (d) 优缺点

| 优势 | 劣势 |
|:----:|:----:|
| 极高的数据扩增倍率 (7800×) | 仅限仿真环境 (Sim-to-Real Gap) |
| 物理精确 (仿真器保证) | 需要任务的物体中心分解 |
| 全自动化，无需人工 | 复杂交互场景难以分解 |
| 成本极低 (11 小时 GPU) | 视觉多样性有限 (仿真渲染) |

## 5. 逆动力学模型：伪动作标注

### (a) 问题

神经轨迹和人类视频只有图像帧，没有机器人动作。如何给这些"无动作视频"添加动作标注？

### (b) IDM (Inverse Dynamics Model) 原理

逆动力学模型从**连续帧的视觉差异**中预测**动作块 (Action Chunk)**：

```
IDM 架构 (GR00T N1):
═══════════════════════════════════════

输入:
  ┌──────────┐  ┌──────────┐
  │ 当前帧 oₜ │  │ 未来帧 oₜ₊ₖ│
  └─────┬────┘  └─────┬────┘
        │              │
        └──────┬───────┘
               ↓
  ┌──────────────────────┐
  │  视觉编码器 (共享)     │
  │  ResNet / ViT         │
  └──────────┬───────────┘
             ↓
  ┌──────────────────────┐
  │  DiT (扩散 Transformer)│
  │  + Flow Matching       │
  │                        │
  │  条件: oₜ 和 oₜ₊ₖ 的特征 │
  │  输出: 动作块 â₁:ₖ       │
  └──────────┬───────────┘
             ↓
  预测动作块:
  â₁:ₖ = [â₁, â₂, ..., âₖ]

  其中每个 âᵢ = [Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]
```

### (c) IDM 的数学形式

IDM 本质上是一个**条件生成模型**：

$$p(a_{1:k} \mid o_t, o_{t+k}) = \int p_\theta(a_{1:k} \mid o_t, o_{t+k}, z) \cdot p(z) \, dz$$

使用 Flow Matching 训练：

$$\mathcal{L}_{\text{IDM}} = \mathbb{E}_{t, a, \epsilon} \left[ \| v_\theta(a_t, t, o_{\text{curr}}, o_{\text{future}}) - u_t(a_t \mid a_1) \|^2 \right]$$

其中 $v_\theta$ 是速度场网络，$u_t(a_t \mid a_1)$ 是最优传输目标速度场。

### (d) IDM vs LAPA 对比

| 维度 | IDM (逆动力学模型) | LAPA (潜在动作预训练) |
|:----:|:-----------------:|:-------------------:|
| **输出空间** | 真实机器人动作空间 (7D) | 潜在离散码本 (K 个 token) |
| **训练数据** | 需要有动作标注的数据 | 只需视频帧 |
| **适用场景** | 给合成视频添加伪动作 | 从人类视频学习操作模式 |
| **架构** | DiT + Flow Matching | VQ-VAE |
| **精度** | 高 (直接预测真实动作) | 中 (需要后训练对齐) |
| **泛化性** | 依赖训练时的机器人类型 | 机器人无关 |

### (e) IDM 在数据金字塔中的位置

```
数据金字塔中 IDM 和 LAPA 的角色:
═══════════════════════════════════════

  第 1 层 (人类视频)  ←── LAPA 提取潜在动作
       ↓
  第 2 层 (合成视频)  ←── IDM 预测伪动作
       ↓                   (在第 3 层数据上训练 IDM)
  第 3 层 (真实数据)  ←── 训练 IDM 模型的监督信号
```

**流程**：
1. 用 **第 3 层** (真实遥操作数据) 训练 IDM
2. 用训练好的 IDM 为 **第 2 层** (神经轨迹) 生成伪动作标注
3. 用 LAPA 为 **第 1 层** (人类视频) 提取潜在动作
4. **所有层的数据一起用于 VLA 预训练**

### (b) LeRobot 扩展标准 (GR00T N1, 2025)

GR00T N1 对 LeRobot 格式提出了四项关键扩展，以支持更复杂的数据管理：

```python
# 1. 模态配置 (Modality Config)
# 声明数据集包含哪些模态及其维度
modality_config = {
    "observation": {
        "image_front": {"type": "image", "shape": [480, 640, 3]},
        "image_wrist": {"type": "image", "shape": [224, 224, 3]},
        "joint_state": {"type": "vector", "dim": 16},
        "ee_pose": {"type": "pose", "dim": 7},
    },
    "action": {
        "type": "target_ee_pose",
        "dim": 7,
        "rotation_type": "rotation_6d",  # ← 旋转类型规范
    },
    "language": {"type": "text", "max_length": 256},
}

# 2. 细粒度模态规范
# 区分不同的传感器输入，而非笼统的 "observation"
fine_grained_spec = {
    "front_camera": {
        "modality": "rgb",
        "resolution": [480, 640],
        "fps": 30,
        "intrinsics": [fx, fy, cx, cy],
    },
    "wrist_camera": {
        "modality": "rgb", 
        "resolution": [224, 224],
        "fps": 15,
    },
}

# 3. 多标注支持
# 同一段视频可以有多种动作标注
annotations = {
    "real_action": np.array([7]),        # 真实遥操作动作
    "idm_pseudo_action": np.array([7]),  # IDM 预测的伪动作
    "lapa_latent_action": np.array([16]),# LAPA 潜在动作 token
}

# 4. 旋转类型规范
# 不同数据集使用不同的旋转表示
rotation_types = {
    "euler_xyz": 3,          # 欧拉角 (奇异值问题)
    "quaternion": 4,         # 四元数 (归一化约束)
    "axis_angle": 3,         # 轴角
    "rotation_6d": 6,        # Zhou et al. 6D 表示 (推荐)
    "rotation_matrix": 9,    # 旋转矩阵
}
```

### (c) 为什么格式标准化很重要？

| 无标准化 | 有标准化 |
|:-------:|:-------:|
| 每个数据集需要单独的数据加载器 | 一个加载器适配所有数据集 |
| 混合训练需要大量胶水代码 | 声明式配置即可混合 |
| 新数据集接入成本高 | 按规范采集即可直接使用 |
| 动作空间不可比 | 统一的归一化和旋转表示 |
| 难以扩展到新模态 | 模态配置可灵活添加 |

## 7. 跨具身训练策略：何时用什么数据

### (a) RoboVLMs 的系统实验 (ByteDance, 2024-2026)

RoboVLMs 论文对**跨具身数据的使用策略**进行了大规模系统性实验，回答了关键问题：**什么时候应该使用跨具身数据？怎么用效果最好？**

```
四种训练策略:
═══════════════════════════════════════

策略 1: Pre-train (预训练)
─────────────────────────
  数据: 跨具身 (OXE) + 目标域数据
  阶段: 主训练阶段就使用混合数据
  流程: {OXE + 目标域} → VLA 模型

策略 2: Co-train (联合训练)
─────────────────────────
  数据: 跨具身 + 目标域混合
  阶段: 两者以一定比例混合训练
  流程: {α·OXE + (1-α)·目标域} → VLA 模型

策略 3: Post-train (后训练)
─────────────────────────
  数据: 先跨具身预训练，再目标域微调
  阶段: 两阶段串行
  流程: OXE → VLA₁ → 目标域微调 → VLA₂

策略 4: Finetune (微调)
─────────────────────────
  数据: 仅目标域数据
  阶段: 仅用目标任务数据微调 VLM
  流程: VLM → 目标域微调 → VLA
```

### (b) 关键实验发现

| 发现 | 具体结论 | 实验证据 |
|:----:|:-------:|:-------:|
| **1. 域内数据最关键** | 增加**同一机器人同一环境**的数据量，效果最显著 | 域内数据 +50% → 成功率 +15%；跨具身数据 +200% → 成功率仅 +3% |
| **2. Post-train 最稳定** | 先用 OXE 预训练再目标域微调，效果最好最稳定 | Post-train > Co-train > Pre-train ≈ Finetune |
| **3. 高频任务受益最大** | 需要精细控制的任务 (如灵巧操作) 从跨具身数据中获益更多 | 桌面整理 +18%；简单抓取仅 +3% |
| **4. VLM 预训练是基础** | 不使用 VLM 预训练的 VLA 几乎无法受益于跨具身数据 | 无 VLM 预训练: 跨具身数据甚至降低性能 |
| **5. 数据比例很重要** | 跨具身数据与目标域数据的比例有一个最优点 | 最优比例约 3:1 (跨具身:目标域) |

### (c) 训练策略选择指南

```
你应该用什么策略？
═══════════════════════════════════════

Q1: 你有足够的域内数据吗？
    │
    ├─ 有 (>10K 轨迹) → 直接 Finetune，跨具身数据帮助有限
    │
    └─ 少 (<10K 轨迹) → 继续 Q2

Q2: 你的任务有多复杂？
    │
    ├─ 简单 (单步抓取) → Co-train (混合 OXE 数据)
    │
    └─ 复杂 (多步操作) → Post-train (先 OXE 预训练再微调)

Q3: 你有 VLM 预训练的 backbone 吗？
    │
    ├─ 有 → Post-train 效果最佳
    │
    └─ 没有 → 先获取 VLM backbone，否则跨具身数据可能有害

实际建议:
┌─────────────────────────────────────────────┐
│  最佳实践 (大多数情况):                        │
│                                             │
│  VLM backbone (如 PaliGemma)                │
│       ↓                                     │
│  Post-train on OXE (全量跨具身数据)           │
│       ↓                                     │
│  Finetune on 目标具身 + 目标环境数据           │
│       ↓                                     │
│  部署                                        │
└─────────────────────────────────────────────┘
```

## 8. 自动驾驶数据引擎深度解析

### (a) VLA vs AD 数据策略的根本差异

| 维度 | VLA (机器人) | AD (自动驾驶) |
|:----:|:-----------:|:------------:|
| **数据采集方式** | 遥操作 (人控制机器人) | 车载传感器 (人正常开车) |
| **采集成本** | 极高 ($50-100/小时) | 低 (车辆正常行驶) |
| **数据规模** | ~10³ 小时 | ~10⁷ 小时 |
| **传感器模态** | RGB 相机 + 力/力矩 + 关节编码器 | LiDAR + 相机 + 雷达 + IMU + GNSS |
| **动作空间** | 6-14 DoF 关节 | 3D: 方向盘 + 油门 + 刹车 |
| **时空覆盖** | 实验室/有限场景 | 全球道路/全天候 |
| **关键瓶颈** | 数据量不足 | 长尾场景覆盖不足 |
| **核心创新方向** | 数据扩增 (合成/视频) | 困难样本挖掘 + 仿真生成 |

#### Tesla 影子模式 (Shadow Mode) 详解

```
影子模式的三层架构:
═══════════════════════════════════════

Layer 1: 全量影子 (All Fleet)
──────────────────────────────
  所有搭载 FSD 硬件的车辆 (>600 万辆)
  • 运行轻量检测器 → 识别"有趣"场景
  • 触发条件: AEB 激活、急转弯、罕见路况
  • 仅上传元数据 (GPS、场景类型、时间戳)
  → 作用: 建立全球场景分布地图

Layer 2: 目标影子 (Targeted Shadow)
──────────────────────────────
  选中的子集车辆 (~100 万辆)
  • 后台运行完整 FSD 模型 (不控制车辆)
  • 比较: 模型预测 vs 人类实际操作
  • 不一致 → 上传 30 秒视频片段
  → 作用: 自动发现模型的具体弱点

Layer 3: 定向挖掘 (Targeted Mining)
──────────────────────────────
  根据 Layer 2 发现的弱点类别
  • 向全车队发送特定触发器
  • 例: "发现模型在环形路口弱 →
    所有车在环形路口时上传数据"
  • 短时间内收集数万个同类场景
  → 作用: 快速补齐特定短板
```

#### Tesla 自动标注流水线 (Auto-Labeling via SfM)

Tesla 的自动标注系统基于**多帧 Structure-from-Motion (SfM)** 重建：

```
原始视频输入: 8 个相机 × 36Hz × 连续帧序列
    │
    ↓
Step 1: 多帧三角化
────────────────────
  • 从连续帧中提取特征点
  • 利用车辆运动 (IMU/轮速) 作为初始位姿
  • 多视角三角化 → 稠密 3D 点云
    │
    ↓
Step 2: 3D 物体检测与跟踪
────────────────────
  • 在时空一致的 3D 点云中检测物体
  • 跨帧关联 → 获得 3D 轨迹
  • 精度: 接近 LiDAR 标注质量
    │
    ↓
Step 3: 自动生成多维标注
────────────────────
  • 3D 检测框 (车辆/行人/自行车)
  • 深度图 (Dense Depth)
  • 占据网格 (Occupancy Grid)
  • 可行驶区域 (Drivable Surface)
  • 车道线 + 交通标志/信号状态
  • 运动预测标签 (其他车辆的未来轨迹)
    │
    ↓
Step 4: 质量过滤
────────────────────
  • 重建置信度评分
  • 时空一致性检查
  • 高置信度标注 → 训练集
  • 低置信度 → 丢弃或人工审核
```

Tesla 的关键优势在于**规模化**：

| 指标 | 数值 |
|:----:|:----:|
| **总行驶数据** | 70 亿+ 英里 (截至 2025) |
| **搭载 FSD 硬件车辆** | >600 万辆 |
| **每日新增里程** | ~1 亿英里 |
| **自动标注比例** | >99% |
| **FSD v13 数据量** | 4.2× v12 |
| **FSD v13 训练算力** | 5× v12 |

#### Tesla 困难样本挖掘策略

| 挖掘方式 | 触发条件 | 典型场景 |
|:--------:|:-------:|:-------:|
| **影子模式不一致** | 模型预测 ≠ 人类行为 | 模型想直行但人类紧急刹车 |
| **高 Loss 样本** | 训练 loss 异常高 | 遮挡严重的路口 |
| **介入事件** | 人类从 FSD 接管控制 | 模型行为不安全 |
| **碰撞/近碰** | TTC < 阈值 | 前方急刹车、行人横穿 |
| **长尾场景** | 场景出现频率极低 | 施工区、紧急车辆、动物 |
| **地理定向** | 特定地点的异常高失败率 | 复杂环形路口、无标线道路 |

#### NVIDIA Cosmos 视频数据策展管线 (2025)

NVIDIA Cosmos 论文详细公开了迄今为止最完整的**大规模视频数据策展流水线**，处理了 2000 万小时原始视频，提取出 1 亿高质量训练片段：

```
Cosmos 视频数据策展 5 步流水线:
═══════════════════════════════════════

原始数据: 20M 小时视频 (720p-4K, 多种编解码器)
                │
                ↓
  Step 1: 分割 (Splitting)
  ──────────────────────
  • 镜头边界检测 (Scene Change Detection)
    → 将长视频切分为无场景切换的短片段
  • 统一转码: h264_nvenc 高码率编码
    → GPU 硬件加速 (NVDEC/NVENC)
    → 吞吐量: 单 L40S 约 820 视频/GPU·小时
                │
                ↓
  Step 2: 过滤 (Filtering)
  ──────────────────────
  2a. 光流评估 (Motion Filtering)
      • 计算帧间光流 → 衡量运动丰富度
      • 过滤静止/低运动视频
  2b. 美学评分 (Aesthetic Scoring)
      • 图像质量评估模型
      • 过滤模糊/过曝/低分辨率
  2c. 文本覆盖检测 (OCR Filtering)
      • 过滤含大面积文字水印的视频
  2d. 视频类型分类 (Type Classifier)
      • VLM 生成标签 → 训练分类器
      • 过滤不适合的类型 (游戏画面/动画等)
      • 上采样物理相关类别 (动作/交互)
      • 下采样不重要类别 (风景/静态)
                │
                ↓
  Step 3: 标注 (Annotation)
  ──────────────────────
  • 使用 VILA VLM 为每段视频生成文本描述
  • 每 256 帧生成一个描述
  • 聚焦物质事实和细节 (非主观描述)
  • 统一的描述风格 → 减少训练噪声
                │
                ↓
  Step 4: 去重 (Deduplication)
  ──────────────────────
  • 语义去重 (Semantic Deduplication)
    → 使用视频嵌入的余弦相似度
  • 构建多样但紧凑的数据集
  • 去除冗余的相似片段
                │
                ↓
  Step 5: 分片 (Sharding)
  ──────────────────────
  • 按分辨率/宽高比/长度分桶
  • 打包为 WebDataset 格式
  • 直接供模型训练消费
  • 分为预训练集 (~10⁸ 片段)和微调集 (~10⁷ 片段)

  最终产出: ~100M 高质量视频片段
  数据分布: 驾驶(11%), 手部操作(16%),
           人体运动(10%), 空间导航(16%),
           第一人称(8%), 自然动态(20%),
           动态相机(8%), 合成渲染(4%), 其他(7%)
```

```
方法 1: 3DGS 场景重建与编辑 (RAD, 2025)
═══════════════════════════════════════
  真实驾驶数据 → 3D Gaussian Splatting 重建 →
  → 场景编辑: 添加/移除车辆、改变天气、调整光照 →

  限制: 需要多视角输入，编辑粒度有限

方法 2: 世界模型视频合成 (GAIA-1/2, DriveDreamer)
═══════════════════════════════════════
  当前帧 + 动作/轨迹 → 世界模型预测未来帧
  → 生成无限驾驶场景变体
  → 特别适合长尾危险场景 (碰撞/近碰)
  代表工作:
    GAIA-1: 9B 参数自回归, 视频+文本+动作条件

方法 3: NeRF/3DGS 大尺度场景重建 (Block-NeRF)
═══════════════════════════════════════

  → 自由视角渲染 → 新路线/新视角训练数据
  → 可改变光照和天气条件
  优势: 覆盖整个城市街区
  限制: 重建计算量大，动态物体处理困难

方法 4: 域随机化 (Domain Randomization)
═══════════════════════════════════════
  在仿真中随机化视觉参数:
    • 纹理/材质随机化
    • 光照方向和强度随机
    • 相机内参/外参添加噪声
    • 对象形状/颜色随机
  → 策略: 看过足够多的变体 → 真实世界变化在范围内

方法 5: 对抗场景生成 (Adversarial Scenario Generation)
═══════════════════════════════════════

    • 产生高价值的困难训练样本
```

### (g) 多传感器数据管理挑战

```
多传感器时空同步问题:
═══════════════════════════════════════

  LiDAR: 10-20 Hz (旋转扫描 → 运动畸变)
  相机:  15-30 Hz (全局快门 vs 卷帘快门)
  雷达:  13-17 Hz (不同测量率)
  IMU:   100-200 Hz (高频惯性测量)
  GNSS:  1-10 Hz (低频定位)

  问题 1: 时间戳对齐
  ──────────────────
    不同传感器的触发时间不完全一致
    → 需要硬件同步 (PPS + PTP)
    → 软件后处理: 插值对齐

  问题 2: 空间标定
  ──────────────────
    不同传感器的坐标系不同
    → 外参标定: LiDAR-Camera, Radar-Camera
    → 在线自标定: 行驶中持续修正

  问题 3: 运动补偿
  ──────────────────
    LiDAR 旋转扫描 (~100ms) 期间车辆在移动
    → 点云运动畸变 (motion distortion)
    → 用 IMU 高频位姿进行逐点补偿

  问题 4: 数据带宽与存储
  ──────────────────
    原始数据: ~1-2 GB/s
    1 小时驾驶 ≈ 3-7 TB 原始数据
    → 需要边缘压缩和选择性上传
    → Tesla: 仅上传"有趣"的 30 秒片段
    → Waymo: 全量记录但后处理筛选
```

### (b) 多层过滤策略

```
GR00T N1 的数据过滤流水线:
═══════════════════════════════════════

Layer 1: 基础过滤
─────────────────────
  • 视频长度异常 (太短 < 1s 或太长 > 120s)
  • 帧间变化为零 (静止视频)
  • 图像质量过低 (模糊/过曝/过暗)

Layer 2: VLM 裁判 (更高级过滤)
─────────────────────
  对神经轨迹 (合成视频):
  
  提问 VLM:
  Q1: "视频中的机器人是否成功完成了任务?"
  Q2: "物体的运动是否物理合理?"
  Q3: "机器人手臂的运动是否平滑连续?"
  
  综合评分 < 阈值 → 丢弃

Layer 3: 动作一致性检查
─────────────────────
  • IDM 预测的伪动作 vs 视频帧间变化是否一致
  • 动作突变检测 (|aₜ - aₜ₋₁| > threshold)
  • 关节极限违规 (预测的关节角超出物理范围)

Layer 4: 训练时动态过滤
─────────────────────
  • 高 loss 样本标记 → 可能是低质量数据
  • 但也可能是困难样本 → 需要区分
  • 策略: 高 loss 但 VLM 评分高 → 保留 (困难样本)
          高 loss 且 VLM 评分低 → 丢弃 (坏数据)
```

### (c) 数据加权策略

不同质量和来源的数据在训练时应赋予不同权重：

$$\mathcal{L} = \sum_{i \in \text{layers}} w_i \cdot \mathcal{L}_i$$

| 数据层 | 权重 $w_i$ | 理由 |
|:------:|:----------:|:----:|
| 真实遥操作 | **1.0** (基准) | 最高质量，直接对应目标 |
| 仿真轨迹 | **0.5 - 0.7** | 物理准确但视觉简化 |
| 神经轨迹 | **0.3 - 0.5** | 视觉真实但动作为伪标注 |
| 人类视频 (LAPA) | **0.1 - 0.3** | 仅提供潜在动作，间接监督 |

| 趋势 | 说明 | 时间线 |

> **一句话总结**：数据工程是 VLA 和自动驾驶模型的核心竞争力——VLA 领域通过金字塔分层策略 + LAPA 潜在动作提取 + 神经轨迹生成解决数据稀缺问题；自动驾驶领域通过 Tesla 影子模式 + Waymo 4D 自动标注 + NVIDIA Cosmos 视频策展 + 世界模型仿真生成解决长尾场景覆盖问题。数据不仅要"多"，更要"对"——域内数据的价值 > 跨具身数据 > 合成数据 > 互联网视频，但所有层级的组合才能达到最优性能。

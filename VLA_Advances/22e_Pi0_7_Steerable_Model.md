# 22e. π0.7：可操控的通用模型与涌现能力（2026.04）

> 本文是 [π0 系列总览](./22_Pi0_Generalist_Policy.md) 的子篇，专注于 π0.7 的多模态 Prompt 框架、组合泛化涌现能力以及与 System 1/2 架构的关系。

> **博客**：*π0.7: a Steerable Model with Emergent Capabilities* (Physical Intelligence, April 2026)

## 1. 动机：从"专家系统"到"通用智能"

π\*0.6 虽然在特定任务上达到了实用级鲁棒性，但本质上仍是**任务特定微调**的产物——每个任务（Espresso、折叠、组装）都有一个独立微调的 π\*0.6 专家模型：

```
π*0.6 的局限 (专家模式):

  π*0.6_espresso  ← 只会做 Espresso
  π*0.6_laundry   ← 只会折衣服
  π*0.6_box       ← 只会装纸箱
  
  问题 1: 新任务 = 新一轮 RL 微调 (昂贵)
  问题 2: 无法组合——"先做咖啡再折衣服" 需要切换模型
  问题 3: 没有泛化——遇到训练中没见过的厨房电器就不会用
```

**真正的通用模型应该像 LLM 那样具备组合泛化**：

```
LLM 的组合泛化:
  知道"英语→法语翻译" + 知道"JSON 格式" 
  → 能做"英法翻译并输出 JSON" (训练中没见过这个组合)

VLA 理想的组合泛化:
  知道"抓取物体" + 知道"空气炸锅长什么样"
  → 能"把红薯放进空气炸锅" (训练中几乎没见过这个任务)
```

π0.7 的目标：**一个模型**，无需微调，既能达到 π\*0.6 专家级的灵巧操作水平，又能组合已学技能解决全新任务。

## 2. 核心创新：多模态 Prompt 框架

π0.7 实现通用性的关键不在于更大的模型或更多的数据，而在于**如何利用数据**——通过多样化的多模态 Prompt 结构，让异构数据在同一个模型中共存而不冲突。

### (a) 异构数据的策略冲突问题

当把异构数据直接混合训练时，模型陷入策略冲突：

```
同一个任务 "fold the towel"，四种数据源给出四种 "答案":

数据源 A (专家示教):  慢速、精确、每个折痕对齐 → 高质量但慢
数据源 B (RL 自主):   快速、略粗糙、偶尔对不齐 → 速度快但有瑕疵
数据源 C (纠错介入):  只包含"从错误状态恢复"的片段 → 局部正确但不完整
数据源 D (人类视频):  只有视觉，没有关节动作 → 有"目标状态"但无运动学

直接混合训练 → 模型学到一个"折中"策略 → 既不够快也不够准
```

### (b) 四维 Prompt 设计

π0.7 为每条训练数据附加一个**结构化的多模态 Prompt**，包含四个正交维度：

```
┌─────────────────────────────────────────────────────────────────────┐
│                   π0.7 Prompt = 四维条件向量                         │
│                                                                     │
│  维度 1: 语言指令 (Language Instruction)                              │
│    "fold the towel"                                                 │
│    → 定义 WHAT: 做什么任务                                           │
│                                                                     │
│  维度 2: 元数据 (Metadata)                                           │
│    quality="high" | "medium" | "low"                                │
│    speed="slow" | "normal" | "fast"                                 │
│    source="demonstration" | "autonomous" | "correction"             │
│    → 定义 HOW WELL: 这条数据的执行质量/策略风格                      │
│                                                                     │
│  维度 3: 控制模态 (Control Modality)                                  │
│    "joint_position" | "end_effector_pose" | "delta_joint"           │
│    → 定义 HOW: 用什么动作空间执行                                     │
│                                                                     │
│  维度 4: 视觉子目标 (Visual Subgoal)                                  │
│    一张"任务完成后应该是什么样"的目标图像                               │
│    → 定义 WHAT IT LOOKS LIKE: 目标状态的视觉规格                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### (c) 冲突消解机制

```
之前 (无 Prompt):
  数据 A: ("fold towel", 慢速精确动作)     ← 模型: 折毛巾 = 慢速？
  数据 B: ("fold towel", 快速粗糙动作)     ← 模型: 折毛巾 = 快速？ 矛盾！

之后 (有 Prompt):
  数据 A: ("fold towel", quality=high, speed=slow, 慢速精确动作)
  数据 B: ("fold towel", quality=medium, speed=fast, 快速粗糙动作)
  
  模型学到的不是一个策略，而是一个 **策略空间**:
    p(action | "fold towel", quality, speed) 
    
  部署时: 设 quality=high, speed=fast → 高质量且快速的策略
  → 模型可以**内插**出训练数据中不存在的策略组合！
```

### (d) 四个维度各自的泛化增益

**元数据维度——把"数据噪声"变成"学习信号"**

传统做法丢弃低质量数据（砍掉 50%+ 数据量）。π0.7 保留所有数据，用元数据标注质量。部署时设 `quality="high"` → 只输出高质量行为。数据量翻倍，且模型隐式学到了"什么样的动作会导致失败"。

**控制模态维度——解耦任务语义与动作空间**

Prompt 中显式指定 `control_modality` → 模型将"抓杯子需要从上方接近并对准中心"的语义知识与具体关节配置解耦 → 跨本体迁移能力大幅增强。

**视觉子目标维度——让纯视觉数据也能参与训练**

互联网上海量人类操作视频只有画面没有关节数据，传统方法无法利用。π0.7 将视频帧作为"视觉子目标"训练，推理时由世界模型实时生成目标图像。

**四维联合——组合泛化**

```
训练时见过的组合:
  ✅ ("fold towel", quality=high, speed=slow, joint_control)
  ✅ ("pick cup",   quality=high, speed=fast, ee_control)

部署时请求的新组合:
  ❓ ("fold towel", quality=high, speed=fast, ee_control)
  → 模型能内插/外推各维度 → 组合出训练中不存在的策略
```

### (e) 训练时 vs 推理时：Prompt 从哪来？

训练时 Prompt 是**对历史数据的描述**，推理时 Prompt 是**对期望行为的指定**：

| Prompt 维度 | 训练时谁提供 | 推理时谁提供 |
|:---|:---|:---|
| **语言指令** | 数据标注 | 高层策略自动生成 / 用户输入 |
| **quality** | 回顾标注（这条数据好不好） | **固定设为 "high"** |
| **speed** | 回顾标注（这次执行快不快） | 按需求设置 |
| **控制模态** | 按数据采集时的配置 | 按部署机器人类型自动选择 |
| **视觉子目标** | 从演示视频中提取的未来帧 | **世界模型实时生成** |

**关键技巧**：推理时永远设 `quality="high"`。即使训练数据中有 50% 是低质量的，推理时全部被条件化过滤——同时获得了更多数据的泛化收益和高质量数据的精度收益。

### (f) 视觉子目标 + 世界模型

```
π0.7 的推理流程:

  高层策略: "清理厨房桌面"
       ↓
  语言子任务: "把碗放到水槽里"
       ↓
  世界模型 (World Model):
    输入: 当前图像 + "把碗放到水槽里"
    输出: 合成的目标图像 (碗在水槽中的样子)
       ↓
  π0.7:
    输入: 当前观测 + 语言子任务 + 视觉子目标 + 元数据
    输出: Action Chunk
```

### (g) 任务分解 vs Prompt 条件化的关系

**常见误解**：多模态 Prompt 是用来把数据分类成原子化场景和动作的。

**实际上**这是两层独立的机制：

| | 层级 1: 任务分解（来自 π0.5） | 层级 2: Prompt 条件化（来自 π0.7） |
|:---|:---|:---|
| **解决什么** | 复杂任务不知从何下手 | 同一原子任务的多种执行策略冲突 |
| **操作对象** | 任务粒度（粗→细） | 策略空间（条件化执行方式） |
| **泛化来源** | VLM 常识推理 | 条件组合的内插/外推 |
| **类比** | 把文章拆成句子 | 同一句话用不同语气说 |

两者缺一不可——没有任务分解，模型面对复杂任务会迷失；没有多模态 Prompt，模型面对混合数据会学出冲突策略。

### (h) 本质：从"一个策略"到"策略的策略"

```
传统 VLA:  p(action | observation, language)
           → 一个输入 → 一个策略

π0.7:     p(action | observation, language, quality, speed, control_mode, visual_goal)
           → 不是学一个策略，而是学一个 **策略生成器**
           → 给定不同的条件组合，生成不同的策略
```

类比 LLM：GPT 不是学会了每一个具体问题的答案，而是学会了"根据 prompt 生成答案的机制"。π0.7 同理——它掌握了**任务的组合规则**。

## 3. 涌现能力：组合泛化 (Compositional Generalization)

π0.7 展示了 VLA 领域**首次观察到的组合泛化现象**。

### 标志性实验：空气炸锅 (Air Fryer)

```
训练数据中的相关经验:
  ① 2 条关闭空气炸锅的数据
  ② DROID 开源数据集中的通用操作数据
  ③ 互联网预训练知识 ("空气炸锅是一种厨房电器")
  
  ❌ 没有"把红薯放进空气炸锅"的完整训练数据

π0.7 的表现:

  零样本 (单条指令):
    → 部分步骤完成 (~5% 成功率)
  
  语言引导 (分步语言指令):
    Step 1: "拿起红薯"
    Step 2: "把空气炸锅的篮子拉出来" 
    Step 3: "把红薯放进篮子"
    Step 4: "把篮子推回去"
    → 成功完成！ (~95% 成功率)

  自主执行 (微调高层策略后):
    → 全自主完成，无需人类引导
```

**为什么这是"涌现"的？**

```
组合来源:
  "拿起物体" ← 来自大量通用抓取数据
  "空气炸锅的外观与操作" ← 来自 2 条数据 + 互联网预训练
  "拉出/推入抽屉式结构" ← 来自抽屉操作的训练数据
  "放置物体到容器中" ← 来自大量放置任务数据
  
  π0.7 = 拿起红薯 ⊕ 识别空气炸锅 ⊕ 拉出篮子 ⊕ 放入 ⊕ 推回
         (组合，而非直接模仿)
```

## 4. 跨本体迁移 (Cross-Embodiment Transfer)

```
实验: 双臂 UR5e 折叠衣服

  训练数据: 折叠衣服的数据全部来自小型双臂静态机器人
  测试平台: 大型双臂 UR5e 工业机械臂 + Robotiq 平行夹爪
  
  两个平台差异巨大:
  - 尺寸: UR5e 臂展远大于训练用机器人
  - 惯性: UR5e 手臂更重，动态特性完全不同
  - 夹爪: 不同的抓取机构
  
  结果: π0.7 在 UR5e 上零样本折叠衣服
  → 成功率与资深人类遥操作员首次使用 UR5e 的水平相当
     (这些遥操作员平均有 375 小时遥操作经验)
```

## 5. 单模型匹敌多个专家

π0.7 的最令人印象深刻之处：**一个通用模型**在各项任务上达到甚至超越了 π\*0.6 专家模型的水平。

| 任务 | π\*0.6 专家 (各自微调) | π0.7 通用模型 (无微调) |
| :--- | :--- | :--- |
| **洗衣折叠 (T恤+短裤)** | 基线 | 吞吐量 ≥ 专家水平 |
| **洗衣折叠 (困难衣物)** | 基线 | 吞吐量 ≥ 专家水平 |
| **Espresso 制作** | 基线 | 成功率持平，吞吐量接近 |
| **纸箱组装** | 基线 | 吞吐量 ≥ 专家水平 |

这是通过将 Recap RL 训练过程中产生的自主经验数据**蒸馏**到 π0.7 中实现的。

## 6. π0.7 的快慢系统 (System 1 / System 2) 架构

### (a) 三层推理架构

π0.7 实际上是**三层**系统，而不是严格的两层：

```
┌──────────────────────────────────────────────────────────────────┐
│  Layer 0: 世界模型 (World Model)          ← 最慢 (百毫秒级)      │
│  功能: 当前图像 + 语言指令 → 生成目标状态图像                      │
│  类比: "想象完成后应该是什么样子" → 心理模拟                       │
│  频率: 每个子任务调用一次 (每 5-30 秒)                            │
│  System 2 属性: ✅ 缓慢、模拟、预测性                             │
├──────────────────────────────────────────────────────────────────┤
│  Layer 1: 高层语义规划器                   ← 慢 (秒级)            │
│  功能: "清理厨房" → ["把碗放水槽", "擦桌子", "关抽屉"]            │
│  System 2 属性: ✅ 缓慢、分析性、需要常识推理                      │
├──────────────────────────────────────────────────────────────────┤
│  Layer 2: 低层动作策略                     ← 快 (~50ms/chunk)     │
│  功能: 当前图像 + 子目标 + Prompt → Action Chunk                  │
│  System 1 属性: ✅ 快速、自动、反射式                              │
└──────────────────────────────────────────────────────────────────┘
```

### (b) π0 系列的 System 1/2 演进

```
π0 (2024.10):     只有 System 1 → 短程任务 OK，长程容易漂移
π0.5 (2025.04):   System 2 + System 1 → 首次能做 10+ 步长程任务
π0.7 (2026.04):   System 2+ + System 2 + System 1 → 世界模型增加"想象力"
```

### (c) 可调控的 System 1

传统快慢系统中 System 1 是固定的，但 π0.7 的多模态 Prompt 让 System 1 变得**可条件化**：

```
传统 System 1:   stimulus → fixed response
π0.7 System 1:   stimulus + context → configurable response

  看到杯子 + quality="high" + speed="fast" → 快速精准抓取
  看到杯子 + quality="high" + speed="slow" → 缓慢精细抓取
  
  → 被 System 2 参数化的 System 1
  → 相当于运动员有意识地调整投球力度——底层是肌肉记忆，但参数由意识预设
```

## 7. 与 Harness Agent 的架构共性

π0.7 与企业级 Agent 架构（如 Harness Agent 的 `Agent = Model + Harness`）展现出架构共性——智能从"单一模型"转向"模型 + 结构化运行时环境"：

| Harness Agent 层级 | π0.7 对应 | 本质 |
|:---|:---|:---|
| **模型层** | VLA 基座模型 | 核心推理/生成能力 |
| **上下文层** | **多模态 Prompt** | 运行时条件化 |
| **工具层** | **世界模型** + 传感器 | 外部能力扩展 |
| **编排层** | **高层策略** | 工作流编排 |
| **治理层** | **元数据约束** | 行为边界控制 |

**关键区别**：Harness Agent 的 Prompt 是**推理时外挂**的（后天装配），π0.7 的多模态 Prompt 是**训练时深度绑定**的（先天内化）——这是 π0.7 能实现组合泛化的根本原因。

## 8. 深入解析：跨本体迁移如何克服异构动作空间

π0.7 能零样本迁移到物理参数完全不同的机械臂上，需要克服一个根本矛盾：不同机器人的自由度、关节数、物理尺度都不同，Action Chunk 的维度也不同。核心解法分**三层**：

### (a) 第一层：动作空间统一——从关节空间投影到末端执行器空间

```
不同机器人的关节数:
  Franka Panda:  7 关节 + 1 夹爪 = 8 维
  UR5e:          6 关节 + 1 夹爪 = 7 维
  双臂 UR5e:     12 关节 + 2 夹爪 = 14 维
  双臂 ARX:      12 关节 + 2 夹爪 = 14 维

解法: 统一到末端执行器 (EE) 空间:
  动作 = [Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper]  → 7 维
          ├── 位置增量 (3D) ──┤├── 姿态增量 (3D) ──┤├─ 开合 ─┤

  → 不管底层是 6 轴还是 7 轴机械臂，末端执行器运动都是 6 自由度 + 夹爪
  → 不同机器人的"物理差异"被逆运动学 (IK) 在底层消化
  → 模型只需学"手应该往哪里移动"，而非"每个关节转多少度"
  
  双臂系统: 两组 7 维拼接成 14 维 (左右臂各自独立)
  不同物理尺度: 逐维归一化到 [-1, 1] 消除
```

### (b) 第二层：控制模态 Prompt——显式告知模型动作空间类型

在 π0.7 的四维 Prompt 中，`control_modality` 维度显式指定输出格式：

```
control_modality = "end_effector_pose"   → 输出 EE 空间增量
control_modality = "joint_position"      → 输出关节绝对位置
control_modality = "delta_joint"         → 输出关节增量

效果: 模型将任务语义与运动学细节解耦
  "抓杯子需要从上方接近并对准中心" ← 任务语义 (机器人无关)
  "UR5e 的第 3 关节转 15°"         ← 运动学细节 (机器人相关)
  
  训练时: 同一个"抓杯子"任务来自不同机器人、不同控制模态的数据共存
  推理时: 根据部署机器人类型自动选择控制模态
  → 模型学到的是任务的本质结构，而非特定机器人的运动学映射
```

### (c) 第三层：Action Chunk 维度处理 + FAST+ 通用 Tokenizer

```
统一 Action Chunk 格式 (50 步 × D_max 维):

  单臂 Franka (D=8):
    [a1, a2, ..., a8, 0, 0, 0, 0, 0, 0]
     ↑ 8 维有效        ↑ padding 到 D_max

  双臂 UR5e (D=14):
    [a1, a2, ..., a14]
     ↑ 14 维全部有效

  + embodiment mask 告诉解码器哪些维度有效
```

FAST+ 通用 Tokenizer（在 **100 万条多机器人轨迹**上预训练）可以将不同机器人的 Action Chunk 映射到**同一个离散 token 空间**，无需为每种机器人重新训练 Tokenizer。

### (d) 视觉：跨本体迁移的关键桥梁

```
杯子在 Franka 的相机里是杯子
杯子在 UR5e 的相机里还是杯子
→ VLM 骨干提取的视觉特征天然是机器人无关的

模型本质上学到的映射:
  "看到杯子在桌面右侧" → "手应该向右下方移动并张开夹爪"
  
  这个 视觉→EE空间运动 的映射是通用的
  底层关节如何实现 EE 运动 → 交给各机器人自己的 IK 解算器
```

### (e) 各层分工总结

| 问题 | 解法 | 处理位置 |
|:---|:---|:---|
| 不同关节数 | 统一到 EE 空间 (7维/14维) + padding | 数据预处理 |
| 不同物理尺度 | 逐维归一化到 [-1, 1] | 数据预处理 |
| 不同控制模态 | Prompt 显式指定 control_modality | π0.7 推理时 |
| 不同 chunk 维度 | 固定 D_max + embodiment mask | Action Expert |
| 不同动作分布 | FAST+ 通用 Tokenizer (100万轨迹预训练) | Action Encoder |
| 不同运动学 | IK 解算器在机器人端处理 | 部署时本地运行 |

> **核心洞察**：π0.7 不是让模型"理解不同机器人的运动学"，而是**把动作表示抬升到机器人无关的抽象层**（EE 空间 + 视觉），然后靠底层 IK 解算器把抽象动作翻译回每个机器人的具体关节指令。这与自然语言处理中"不同语言映射到同一语义空间"的思路完全一致。

## 9. π0.7 的主要贡献总结

| # | 贡献 | 意义 |
| :--- | :--- | :--- |
| **C1** | **多模态 Prompt 框架** | 语言+元数据+控制模态+视觉子目标的统一 Prompt 设计，让异构数据和谐共存于同一模型 |
| **C2** | **VLA 领域首次组合泛化** | 模型能组合不同任务中的技能解决从未见过的新任务（空气炸锅实验） |
| **C3** | **通用模型 ≥ 专家模型** | 单一 π0.7 在所有任务上匹配甚至超越各自独立 RL 微调的 π\*0.6 专家模型 |
| **C4** | **强跨本体迁移** | 零样本迁移到物理特性完全不同的机器人平台，成功率与资深人类遥操作员首次尝试持平 |
| **C5** | **可操控性 (Steerability)** | 通过元数据控制执行速度和质量，部署时可按需调节机器人行为策略 |
| **C6** | **世界模型辅助视觉子目标** | 轻量级世界模型在推理时生成目标图像，为动作策略提供精确的空间布局目标 |

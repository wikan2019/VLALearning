## 1. 论文动机与核心问题

### 1.1 交通仿真面临的根本矛盾

自动驾驶的闭环交通仿真需要同时满足两个核心需求：**真实性 (Realism)** 和 **可控性 (Controllability)**。但现有方法在这两者之间存在根本性的矛盾：

```
交通仿真的两难困境:
═══════════════════════════════════════════════════════════════════════

  方法 A: 数据驱动仿真器 (Data-Driven Simulator)
  ──────────────────────────────────────────────
    代表: Waymax, nuPlan, SMART, Trajeglish
    方法: 模仿学习 (IL) 从真实数据学习驾驶行为
    
    ✓ 真实性高: 从真实驾驶数据学到的轨迹分布很逼真
    ✓ 多模态:   能学到多种不同的驾驶风格
    ✗ 协变量漂移:  开环训练 → 闭环部署时分布偏移 → 误差累积
    ✗ 动力学简化:  统一的车辆动力学模型，环境交互不真实
    ✗ 可控性差:    难以生成用户指定的交互行为
    
  方法 B: 物理仿真器 (Physics-Based Simulator)  
  ──────────────────────────────────────────────
    代表: CARLA, SUMO
    方法: RL 在物理引擎中学习，或规则驱动
    
    ✓ 可控性强: 通过物理引擎精细控制场景配置
    ✓ 闭环交互: 高保真的闭环物理交互
    ✗ 真实性差: 没有大规模专家示范 → 行为不像人类
    ✗ 行为单一: RL 策略容易收敛到特定模式
    
═══════════════════════════════════════════════════════════════════════
  
  核心问题: 如何同时获得两者的优势？
  
  RIFT 的答案: "Pre-training + Fine-tuning" 范式
    → 阶段 1: 在数据驱动仿真器中 IL 预训练 → 获得真实性 + 多模态
    → 阶段 2: 在物理仿真器中 RL 微调 → 获得可控性 + 消除协变量漂移
```

### 1.2 现有闭环微调方法的不足

在 RIFT 之前，已有一些尝试将 IL 和 RL 结合的工作，但都有显著缺陷：

| 现有方法 | 缺陷 |
|---------|------|
| **纯 RL 微调** (PPO/SAC) | 整个模型被 RL 更新 → 破坏预训练学到的真实轨迹分布 |
| **混合 IL+RL** (RTR, RS) | 只对最佳轨迹/执行动作计算 loss → 忽略其他候选轨迹 → 丧失多模态性 |
| **监督微调** (CAT-K) | 依赖专家示范 → 数据收集成本高，扩展性差 |
| **RLHF** (TrafficRLHF) | 需要人工标注 → 成本极高，奖励模型不稳定 |

RIFT 的核心创新就是解决上述所有问题。

### 2.1 整体架构

RIFT 提出了一个 **双阶段以 AV 为中心的仿真框架**：

### 2.2 核心创新点

RIFT 有三个关键技术创新：

```
创新 1: GRPO-style 分组相对优势
───────────────────────────────────
  传统 RL: 只评估被执行的动作/最佳轨迹
  RIFT:   评估所有 G = N_ref × N_lon 条候选轨迹
  
  → 保留多模态驾驶行为 (如左拐、右拐、等待都有可能)
  → 灵感来自 LLM 的 GRPO/DeepSeekMath

创新 2: 去除 KL 正则化
───────────────────────────────────
  传统 RLHF/GRPO: 用 KL(π_θ || π_ref) 约束新策略不要偏离参考策略太远
  RIFT:          去除 KL → 因为 IL 预训练分布可能与用户需求差异大
  
  → 允许更灵活的行为调整 (如从"保守"调整为"激进")
  → 但引发训练不稳定问题 → 用 Dual-Clip 解决

创新 3: Dual-Clip 替代 KL 正则化
───────────────────────────────────
  问题: 去除 KL 后，importance ratio ρ_i 可能爆炸
        当 π_θ(τ_i|s) >> π_θ_old(τ_i|s) 且 Â_i < 0 时
        → ρ_i · Â_i 产生巨大负值 → 梯度不稳定
  
  解决: Dual-Clip (来自 MOBA 游戏 RL)
        max(min(ρ_i · Â_i, clip(ρ_i, 1-ε, 1+ε) · Â_i), c · Â_i)
        
        c > 1: 为负优势设置下界
        → 无论 ρ 多大，损失都不会低于 c·Â_i
        → 梯度被严格限制，训练稳定
```

## 3. 技术细节

### 3.1 CBV 关键背景车辆识别

RIFT 不对所有背景车辆建模，而是只识别**关键背景车辆 (Critical Background Vehicles, CBVs)**——最可能与自车发生交互的车辆：

```
CBV 识别算法:
═══════════════════════════════════════════════════════

  输入: AV 全局路径 𝒫 = {p₁, p₂, ..., p_M}
        所有背景车辆 𝒱_BV = {𝒱₁, 𝒱₂, ..., 𝒱_N}

  对每个背景车辆 𝒱_i:
    1. 用 A* 算法计算 𝒱_i 到路径点 p_k 的估计距离 D̂(p_k, 𝒱_i)
    2. 用 A* 算法计算 AV 到同一路径点 p_k 的估计距离 D̂(p_k, 𝒱_AV)
    3. 计算距离差:
       |D̂(p_k, 𝒱_i) - D̂(p_k, 𝒱_AV)| < δ (阈值, δ = 15m)
    
    如果距离差 < δ → 选为 CBV (目的地相近，可能交互)

  对 CBV: 用 RL 微调的轨迹生成模型控制
  对非 CBV: 继续使用规则驱动 → 减少计算开销

  ┌─────────────────────────────────┐
  │                                 │
  │   AV ───────→ 目标             │
  │    ↑                           │
  │    │ 路径重叠/接近              │
  │    ↓                           │
  │   CBV ───→ 相近目的地           │ ← 高交互概率，选为 CBV
  │                                 │
  │   BV₁ ───→ 远处目的地           │ ← 低交互概率，保持规则控制
  │   BV₂ ───→ 远处目的地           │
  │                                 │
  └─────────────────────────────────┘
```

### 3.2 轨迹生成模型 (基于 Pluto)

RIFT 采用 **Pluto** 作为底层轨迹生成模型。Pluto 的架构如下：

```
Pluto 轨迹生成模型架构:
═══════════════════════════════════════════════════════

  输入:
  ─────
  F_cbv:      CBV 当前状态特征
  F_neighbor: 邻近车辆历史特征 (N_neighbor 辆)
  F_map:      矢量化地图特征 (N_map 个元素)
  
  编码器 (冻结):
  ────────────
  1. 独立编码:
     E_cbv ∈ ℝ^{1×D}
     E_neighbor ∈ ℝ^{N_neighbor×D}
     E_map ∈ ℝ^{N_map×D}
  
  2. 拼接 + 位置编码:
     E_s = concat(E_cbv, E_neighbor, E_map) + PE
     E_s ∈ ℝ^{(1+N_neighbor+N_map)×D}
  
  3. N 层 Transformer Encoder:
     E_s^i = E_s^{i-1} + MHA(LayerNorm(E_s^{i-1}))
     E_s^i = E_s^i + FFN(LayerNorm(E_s^i))
     → 最终 E_enc
  
  解码器 (冻结):
  ────────────
  1. 纵-横向解耦:
     Q_lat ∈ ℝ^{N_ref×D}  (横向查询, 来自参考线)
     Q_lon ∈ ℝ^{N_lon×D}  (纵向查询, 可学习)
     Q_nav = Projection(concat(Q_lat, Q_lon))
     Q_nav ∈ ℝ^{N_ref×N_lon×D}
  
  2. N 层 Decoder:
     Q̂_nav^{i-1} = SelfAttn(SelfAttn(Q_nav^{i-1}, dim=0), dim=1)  # 纵横交叉注意力
     Q_nav^i = CrossAttn(Q̂_nav^{i-1}, E_enc, E_enc)  # 与场景交互
  
  3. MLP 头:
     轨迹: 𝒯 = MLP(Q_dec) ∈ ℝ^{N_ref×N_lon×T×6}
     分数: 𝒮 = MLP(Q_dec) ∈ ℝ^{N_ref×N_lon}
     
     每个轨迹点: [p_x, p_y, cos θ, sin θ, v_x, v_y]
  
  评分头 (微调):
  ────────────
     选择得分最高的轨迹执行
     ← RIFT 只微调这个评分头！
```

**关键设计决策**: RIFT **只微调轨迹评分头**，冻结编码器和解码器：

```
为什么只微调评分头？
═══════════════════════════════════════

  ┌──────────────────────────────────────────────────┐
  │  组件          │  冻结/微调  │  理由               │
  ├──────────────────────────────────────────────────┤
  │  场景编码器     │  冻结 ❄️    │  保留场景理解能力     │
  │  轨迹解码器     │  冻结 ❄️    │  保留轨迹级真实性     │
  │  轨迹评分头     │  微调 🔥    │  重新排序 → 改变行为  │
  └──────────────────────────────────────────────────┘
  
  直觉:
  ─────
  预训练后，模型已经能生成 G = N_ref × N_lon 条多模态轨迹
  问题不是"生成不了好轨迹"，而是"选错了轨迹"
  
  例如:
    候选轨迹包含: 激进超车、保守跟车、等待、变道...
    IL 评分: 选择最像人类的 → 但可能闭环下不安全
    RIFT 评分: 根据奖励重新排序 → 选择闭环下最优的
    
  好处:
    • 轨迹质量不被破坏 (来自 IL 预训练)
    • 多模态性保留 (所有候选轨迹仍然存在)
    • 只有评分头的参数被更新 → 训练快、稳定
```

### 3.3 RIFT 目标函数

RIFT 的数学核心是一个三层嵌套的目标函数：

**Step 1: 计算轨迹级分组相对奖励**

给定状态 $s$，生成 $G = N_{ref} \times N_{lon}$ 条候选轨迹 $\mathcal{T} = \{\tau_i\}_{i=1}^{G}$，计算每条轨迹的累积奖励：

$$r_i = \sum_{t=0}^{T} \gamma^t \cdot \text{StateWiseRM}(\tau_i^t)$$

其中 $\text{StateWiseRM}$ 是逐状态奖励模型（详见 3.4 节）。

**Step 2: 计算分组相对优势**

$$\hat{A}_i = \frac{r_i - \text{mean}(\mathcal{R})}{\text{std}(\mathcal{R})}, \quad \forall i = 1, \ldots, G$$

这里 $\mathcal{R} = \{r_i\}_{i=1}^{G}$ 是组内所有轨迹的奖励集合。**关键**: 优势是相对于组内平均值的偏差，不需要额外的 Critic 网络。

```
分组相对优势的直觉:
═══════════════════════════════════════

  例: G = 6 条候选轨迹

  轨迹 1 (左转激进):   r₁ = 0.8    Â₁ = +1.2   → 正优势 → 增大选择概率
  轨迹 2 (左转保守):   r₂ = 0.6    Â₂ = +0.3   → 轻微正优势
  轨迹 3 (直行):       r₃ = 0.5    Â₃ = -0.1   → 轻微负优势
  轨迹 4 (右转):       r₄ = 0.4    Â₄ = -0.5   → 负优势 → 减小选择概率
  轨迹 5 (等待):       r₅ = 0.2    Â₅ = -1.1   → 强负优势
  轨迹 6 (急刹):       r₆ = 0.1    Â₆ = -1.8   → 最强负优势

  mean(ℛ) = 0.43,  std(ℛ) = 0.26
  
  → 好的轨迹被鼓励，差的被抑制
  → 但所有轨迹都参与计算 → 保留多模态性
    (不只评估执行的那一条！)
```

**Step 3: RIFT 的 Dual-Clip 目标函数**

$$\mathcal{J}_{RIFT}(\theta) = \mathbb{E}_{\{\tau_i\}_{i=1}^G \sim \pi_{\theta_{old}}(s)} \frac{1}{G} \sum_{i=1}^{G} \max\left[\min\left[\rho_i(\theta) \hat{A}_i, \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon) \hat{A}_i\right], c \cdot \hat{A}_i\right]$$

其中：
- $\rho_i(\theta) = \frac{\pi_\theta(\tau_i|s)}{\pi_{\theta_{old}}(\tau_i|s)}$ 是轨迹级重要性采样比
- $\epsilon = 0.2$ 是PPO的裁剪范围
- $c = 3$ 是 Dual-Clip 的下界常数

```
三层嵌套的 max-min-clip 的作用:
═══════════════════════════════════════════════════════

  最内层: min(ρ·Â, clip(ρ, 1-ε, 1+ε)·Â)
  ─────────────────────────────────────
    → 标准 PPO-Clip: 当 ρ 偏离 1 太远时裁剪
    → 防止正优势下策略更新过大
  
  最外层: max(内层结果, c·Â)
  ─────────────────────────────────────
    → Dual-Clip: 为负优势设置下界
    → 当 Â < 0 时:
      • 如果 ρ 很大 (新策略远离旧策略)
      • ρ·Â 会变成很大的负值
      • Dual-Clip 保证结果 ≥ c·Â (c=3)
      • → 梯度被严格限制
  
  对比:
  ┌──────────────────────────────────────────────────────┐
  │              │  ρ 小 (策略没变)  │  ρ 大 (策略改变大)  │
  ├──────────────────────────────────────────────────────┤
  │  Â > 0       │  ρ·Â              │  (1+ε)·Â  裁剪     │
  │  (好轨迹)    │  正常梯度          │  限制更新幅度       │
  ├──────────────────────────────────────────────────────┤
  │  Â < 0       │  ρ·Â              │  c·Â  下界裁剪      │
  │  (差轨迹)    │  正常梯度          │  ✓ Dual-Clip 生效！ │
  │              │                   │  梯度不会爆炸       │
  └──────────────────────────────────────────────────────┘
```

**与 GRPO (LLM) 的对比：**

| 方面 | GRPO (DeepSeekMath/LLM) | RIFT (交通仿真) |
|------|------------------------|----------------|
| **分组方式** | 同一 prompt 生成多个回答 | 同一场景生成多条轨迹 |
| **优势计算** | 组内相对奖励归一化 | 相同 |
| **KL 正则化** | $\beta \cdot \mathbb{D}_{KL}(\pi_\theta \| \pi_{ref})$ | **去除** (允许自由偏离) |
| **裁剪机制** | 标准 PPO-Clip | **Dual-Clip** (解决去除 KL 后的不稳定) |
| **更新对象** | 完整 LLM 参数 | **只有评分头参数** |

### 3.4 奖励函数设计

RIFT 使用**逐状态奖励模型** (StateWiseRM)，不需要前向仿真：

$$R = R_{collision} + R_{off\text{-}road} + R_{comfort} + R_{lane} + R_{velocity} + R_{timestep}$$

各分项详解：

```
奖励函数分解:
═══════════════════════════════════════════════════════════

  R_collision = -(α_collision + |v|) · 𝟙_collision
  ─────────────────────────────────────────────
    碰撞惩罚，速度越高惩罚越大
    直觉: 高速碰撞比低速碰撞危险得多

  R_off-road = -α_boundary · 𝟙_boundary
  ─────────────────────────────────────────────
    驶出可行驶区域的惩罚

  R_comfort = -α_comfort · (𝟙_{|a|>4} + 𝟙_{|ω|>4})
  ─────────────────────────────────────────────
    加速度/角加速度过大时的舒适度惩罚

  R_lane-align = α_l-align · [min(cos(θ_f), 0) + α_vel-align · min(cos(θ_f)·v, 0)
                + 0.25 · (1 - |θ_f|/(π/2))]
  ─────────────────────────────────────────────
    引导车辆沿车道方向行驶，保持与车道标线平行

  R_lane-center = -α_l-center · 𝟙_{cos(θ_f)>0.5} · (|x_f - α_center-bias| - 0.05)
                  / exp(|x_f - α_center-bias| - 0.5)
  ─────────────────────────────────────────────
    引导车辆保持在车道中心

  R_velocity = α_velocity · max(cos(θ_f), 0) · |v| · 𝟙_{13<|v|<20}
  ─────────────────────────────────────────────
    鼓励保持合理速度范围 (13-20 m/s)

  R_timestep = -α_timestep · 𝟙_{|v|>0 ∨ |a|>0}
  ─────────────────────────────────────────────
    每步小惩罚，鼓励效率
    静止时关闭 → 允许路口合理等待

  特征提取:
  φ(τ_i^t) = (𝟙_collision, 𝟙_boundary, a_long, a_lat, θ_f, x_f, v, a)

  碰撞检测: 前向预测其他车辆位置 → bounding box 重叠
  出界检测: Euclidean Signed Distance Field (ESDF)
```

**可控性设计**: 通过调整奖励权重实现不同驾驶风格：

| 风格 | 碰撞惩罚 | 速度奖励 | 效果 |
|------|---------|---------|------|
| **Normal (保守)** | 高 | 中 | 安全优先，保守跟车 |
| **Aggressive (激进)** | 低 | 高 | 效率优先，主动超车 |


## 6. 理论分析

### 6.1 收敛性证明

RIFT 在论文中提供了严格的理论分析。在二值奖励设定 ($r \in \{0, 1\}$) 下：

**引理 A.2 (连续性和区间映射)**:
对每个 $p \in [0,1]$，更新后的成功概率 $h_\epsilon(p) \in (0,1)$，且 $h_\epsilon$ 在 $[0,1]$ 上连续。

**命题 A.3 (固定点存在性)**:
至少存在一个固定点 $p^\star \in (0,1)$，满足 $p^\star = h_\epsilon(p^\star)$。

**定理 A.4 (RIFT 收敛性)**:
假设 $c > 1, \epsilon > 0$。如果 $|h_\epsilon(p) - h_\epsilon(p')| \leq \lambda |p - p'|$ 对某个 $\lambda < 1$ 成立（例如选择步长 $\eta < 1/L(c, \epsilon)$），则：
- (a) $h_\epsilon$ 有唯一固定点 $p^\star \in (0,1)$
- (b) 任何序列 $p_n = h_\epsilon(p_{n-1})$ 几何收敛: $|p_n - p^\star| \leq \lambda^n |p_0 - p^\star|$
- (c) Dual-clip 消除负优势引起的梯度爆炸，保证稳定学习

### 6.2 梯度爆炸消除

Dual-Clip 的核心保证：

$$f_\epsilon^{RIFT}(\rho_i, \hat{A}_i) \geq c \cdot \hat{A}_i$$

因此：

$$|\nabla_\theta \mathbb{E}[f_\epsilon^{RIFT}]| \leq |\nabla_\theta \mathbb{E}[\rho_i \hat{A}_i]|$$

Dual-Clip 将最坏情况下的梯度幅值严格限制在有界范围内。

## 7. 讨论与局限

### 7.1 主要优势

```
RIFT 优势总结:
═══════════════════════════════════════

  1. 真实性 + 可控性: 首次在闭环仿真中同时实现两者
  2. 多模态保留: GRPO-style 评估所有候选轨迹，不丧失行为多样性
  3. 轻量微调: 只微调评分头 → 8 小时单 GPU → 极低成本
  4. 理论保证: 收敛性和稳定性有严格数学证明
  5. 即插即用: 可在任何 IL 预训练模型上使用
  6. 灵活可控: 通过修改奖励权重调整驾驶风格
```

### 7.2 局限性

1. **逐状态奖励模型局限**: StateWiseRM 不做前向仿真，对长时间轨迹的奖励估计可能不准确，导致舒适度优化不足
2. **PID 控制器的舒适度问题**: 轨迹点之间速度跳变 → PID 控制器放大为加速度震荡 → 所有方法都有舒适度弱点
3. **仅支持矢量化输入**: 当前框架只支持完全可观察的矢量化场景表示，不支持端到端 (摄像头输入) 的 AV 方法
4. **单 CBV**: 当前实现通常只识别一个 CBV，多 CBV 交互的扩展有待研究
5. **Sim-to-Real Gap**: 在 CARLA 中微调可能导致过拟合仿真器特性

### 7.3 未来方向

- 扩展到端到端 (camera-in) 的闭环训练和评估
- 设计更好的轨迹级奖励模型 (考虑长期后果)
- 多 CBV 协同交互
- 从 CARLA 迁移到更真实的仿真器 (如 3DGS 重建场景)

| 公式 | 表达式 | 作用 |
|------|-------|------|
| 轨迹奖励 | $r_i = \sum_t \gamma^t \text{RM}(\tau_i^t)$ | 累积折扣奖励 |

| PPO-Clip | $\min(\rho \hat{A}, \text{clip}(\rho) \hat{A})$ | 限制正优势下的更新 |

| 梯度界 | $\|∇\mathcal{J}_{RIFT}\| \leq \|∇\mathbb{E}[\rho \hat{A}]\|$ | 训练稳定性保证 |
| 收敛 | $\|p_n - p^\star\| \leq \lambda^n \|p_0 - p^\star\|$ | 几何收敛 |

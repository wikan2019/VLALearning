## 一、3DGS + SAM/CLIP：语义高斯

### 核心思想

```
原始 3DGS: 每个高斯只有几何属性 (位置/协方差/颜色/不透明度)
语义高斯: 每个高斯额外携带语义特征向量 → 可开放词汇查询
```

### 代表工作

| 工作 | 时间 | 方法 | 能力 |
|:---|:---|:---|:---|
| **Gaussian Grouping** | 2024.04 ECCV | SAM mask → 高斯分组 | 物体级分割/编辑/移除 |
| **Feature 3DGS** | 2024.03 | 蒸馏 CLIP/DINO 特征到高斯 | 开放词汇 3D 检索 |
| **LangSplat** | 2024.05 CVPR | CLIP 特征场 + 3DGS | 语言查询 3D 定位 |
| **LEGaussians** | 2024.06 | 语言嵌入高斯 | 文本→3D 分割 |
| **SAGA** | 2024.08 | SAM + 3DGS 自动分割 | 任意粒度分割 |
| **GARField** | 2024.09 | 分层语义高斯场 | 多粒度语义理解 |
| **OpenGaussian** | 2025.01 | 开放词汇 3DGS | 任意概念的 3D grounding |
| **GOI** | 2025.03 | 互联网图片→语义高斯 | 无需 posed 图像 |

### 技术细节

```
方法 1: 特征蒸馏 (Feature 3DGS / LangSplat)
  训练时:
    - 用 CLIP/DINO 对训练图像提取像素级特征
    - 每个高斯额外学习一个 d 维特征向量 (d=512 for CLIP)
    - Loss = ||rendered_feature - CLIP_feature||²
  
  推理时:
    - 输入文本 "red cup" → CLIP text encoder → 查询向量
    - 在 3D 空间中与每个高斯的特征相似度对比
    - 高相似度高斯 = 目标物体

方法 2: 分割引导分组 (Gaussian Grouping / SAGA)
  - SAM 在 2D 图像中生成 mask
  - 多视图 mask 一致性 → 将高斯聚合为 3D 物体组
  - 每组高斯可独立编辑/移除/移动
```

### 当前水平

```
开放词汇 3D 分割:
  - mIoU: ~65-75% (ScanNet 语义分割)
  - 渲染速度: 仍保持 100+ FPS (语义渲染额外 ~5ms)
  - 支持任意文本查询

物体级操作:
  - 移除物体 + 自动修复背景
  - 复制/移动物体到新位置
  - 风格迁移 (只改某个物体的外观)
```

## 二、3DGS + LLM：语言驱动 3D 编辑

### 代表工作

| 工作 | 时间 | 方法 | 能力 |
|:---|:---|:---|:---|
| **GaussianEditor** | 2024.03 | InstructPix2Pix + 3DGS | 文本指令编辑场景 |
| **GaussCtrl** | 2024.06 | 多视图一致性控制 | 精确局部编辑 |
| **TIP-Editor** | 2024.08 | 文本+图像提示编辑 | 精细外观控制 |
| **Chat-3DGS** | 2025.02 | LLM 理解场景 + 编辑 | 对话式 3D 编辑 |
| **3D-GPT** | 2025.04 | GPT-4 驱动 3D 生成 | 多步推理+生成 |
| **SceneAgent** | 2025.06 | LLM Agent + 3DGS 工具链 | 复杂场景编辑 |

### 技术流程

```
GaussianEditor:
  1. 用户输入: "把椅子变成蓝色"
  2. LLM/CLIP 定位目标: 找到"椅子"对应的高斯组
  3. InstructPix2Pix 生成编辑后的 2D 视图
  4. 多视图一致性: 确保不同角度编辑结果一致
  5. 仅更新目标高斯的颜色/SH系数 → 局部编辑

Chat-3DGS:
  用户: "帮我把客厅重新布置一下"
  LLM: 分析场景 → 规划步骤:
    1. 识别当前家具布局
    2. 提出新布局方案
    3. 调用编辑工具逐个移动/旋转物体
    4. 渲染结果给用户确认
```

### 当前能力

```
  ✅ 改颜色/材质 ("make the table wooden")
  ✅ 添加/移除物体 ("add a plant on the table")
  ✅ 改变风格 ("make it look like a cartoon")
  ⚠️ 精确几何改变困难 ("make the table 10cm taller")
  ❌ 复杂物理交互 ("break the vase")
```

## 三、3DGS + VLA：高斯表示的世界模型

### 代表工作

| 工作 | 时间 | 方法 | 应用 |
|:---|:---|:---|:---|
| **GaussianGrasping** | 2024.08 | 高斯→抓取点估计 | 机器人抓取 |
| **GraspSplats** | 2024.11 | 语义高斯引导抓取 | 开放词汇抓取 |
| **SplatSim** | 2025.01 | 高斯场景仿真 | Sim2Real |
| **GaussianWorld** | 2025.03 | 3DGS 动态世界模型 | 自动驾驶预测 |
| **GS-World** | 2025.05 | 高斯 + 物理引擎 | 机器人规划 |
| **RoboGS** | 2025.07 | 机器人操作的高斯世界模型 | VLA 训练 |
| **DrivingGaussian** | 2025.04 | 驾驶场景高斯世界模型 | 闭环仿真 |

### 三种结合方案

#### 方案 A: 3DGS 作为仿真环境

```
真实场景 → 3DGS 重建 → 高斯场景
→ 放置虚拟机器人/车辆
→ 渲染任意视角图像 → 作为 VLA 输入
→ VLA 输出动作 → 更新高斯场景状态

优势:
  - 比 MuJoCo 渲染更真实
  - 从真实数据构建 → domain gap 小
  - 实时渲染 → 高效采样

局限:
  - 高斯没有碰撞/质量属性 → 需外挂物理引擎
  - 物体移动后需实时更新高斯位置
```

#### 方案 B: 3DGS 作为状态表示

```
观测 → 构建/更新 3DGS → 世界模型状态
→ 在高斯空间中预测动作效果
→ 用预测结果辅助规划

核心模型:
  输入: 当前 3DGS 状态 G + 动作 a
  输出: 下一时刻 3DGS 状态 (每个高斯的新位置/旋转)
  Δg_i = f_θ(G, a)

与 VLA 结合:
  π(a|o) → π(a|G)
  策略输入从图像变为 3D 高斯表示
  → 天然包含 3D 几何信息
```

#### 方案 C: 3DGS 数据增强

```
少量真实数据 → 重建 3DGS → 新视角渲染 → 数据增强

应用:
  50 个抓取演示 → 3DGS → 500+ 增强视角 → 更鲁棒的策略
  语义高斯 + 文本指令 → 定位目标 → 规划抓取
```

### 与 π0 的潜在结合

```
当前 π0:
  输入: 2D 图像 + 本体感受
  局限: 纯 2D 特征，3D 推理隐式

π0 + 3DGS 可能形态:

方案 1: 3DGS 作为额外输入
  图像 → 3DGS 重建 → 高斯特征 → 拼接到 VLM 输入
  代价: 增加推理延迟 (~100ms)

方案 2: 3DGS 作为世界模型
  π0 输出候选动作 → 3DGS 预测结果 → 选最佳动作
  类似 MPC 思路
  代价: 需要准确的动力学预测

方案 3: 3DGS 数据增强
  少量演示 → 3DGS → 多视角增强 → 更多训练数据
  50 条 → 等效 500+ 条
  已有 SplatSim 验证可行性
```

## 四、未来方向 (2026+)

```
① Universal Gaussian Model:
   类似 LLM，训练大规模高斯生成模型
   任意图像 → 前馈生成高质量 3DGS (无需逐场景优化)

② Physics-Aware Gaussians:
   每个高斯携带物理属性 (质量/摩擦/弹性)
   支持物理模拟+渲染统一

③ 3DGS Foundation World Model:
   大规模预训练的 3D 世界模型
   输入: 当前 3DGS + 动作 → 输出: 未来 3DGS
   统一仿真+规划+渲染

④ Robot-ready 3DGS:
   针对机器人部署优化
   实时增量更新 + 语义标注 + 碰撞检测
   替代传统点云/voxel 地图
```
